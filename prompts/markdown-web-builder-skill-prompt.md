# 创建可复用的 Markdown 网页开发 Agent Skill Prompt

请将“读取设计模板 → 研究主题 → 分析技术架构 → 编写或扩展代码 → 建立页面 Markdown → 渲染网页 → 自检”的工作流，整理为一个可以重复使用的 Agent Skill。

## 1. Skill 目标

该 Skill 用于在用户需要生成网页时，根据页面需求选择合适的风格 Prompt，读取其中的设计、架构和 UI 规则，并将新的网页需求转化为可运行的网页项目。

每次执行时需要：

1. 识别用户的页面需求和期望风格；
2. 从可用的风格 Prompt 中选择合适的设计模板；
3. 读取所选模板的设计、架构和 UI 规则；
4. 研究用户提出的主题和目标；
5. 检查当前项目的技术架构；
6. 根据项目状态决定新建或复用 Markdown；
7. 通过程序代码实现或扩展网页能力；
8. 通过页面 Markdown 配置本次内容和表现；
9. 使用当前项目对应的渲染方式生成网页；
10. 对生成结果进行结构、视觉和功能自检。

该 Skill 不应绑定 React、Vue、HTML、Ant Design 或任何固定框架。

## 2. 触发时机

当用户明确要生成网页、新页面或网站时触发。Skill 的默认入口是“生成网页”，而不是单独修改某个 Markdown 文件。

触发后必须先识别并读取当前可用的风格 Prompt，再开始页面设计和代码实现。

风格 Prompt 可以有多个，例如：

```text
trading-style-web-prompt
editorial-style-web-prompt
saas-style-web-prompt
```

Skill 不得假设只有一个固定风格，也不得把某个项目的设计细节写成所有项目的通用规则。

如果用户只是修改已有页面的单个文字或样式，可以直接修改当前项目的 Markdown 或代码，不必重新执行完整流程。

## 3. 设计原则

Skill 需要保留视觉风格、颜色和主题原则、字体层级、页面层级、布局方法、数据展示原则、交互模式、响应式规则和可读性要求。

Skill 不得写死当前项目的页面数量、导航名称、固定区块、业务文案、具体组件库或具体框架。新项目应继承设计语言，但可以自由增加、删除和重新组合页面区块。

设计模板记录“如何设计”，页面 Markdown 记录“本次展示什么”。除非用户明确要求沉淀新的通用规则，否则不得把当前页面细节写回风格 Prompt。

## 4. 代码与 Markdown 的协同模式

程序代码负责框架适配、页面渲染、组件实现、数据请求和处理、API、业务逻辑、交互行为、状态管理、Markdown 解析、主题和布局实现能力、默认配置及错误处理。

Markdown 负责页面文案、标题、导航名称、页面区块、区块顺序、组件参数、数据展示方式、主题配置、布局参数、显示和隐藏条件，以及加载、空状态和错误提示文案。

代码定义“能做什么”，Markdown 决定“当前页面怎么使用”。两者共同控制最终渲染结果。AI 仍然需要在代码上开发；代码新增能力后，必须同步更新 Markdown 规范或示例，使该能力可以通过 Markdown 配置。

## 5. 技术架构识别

执行时必须先检查当前项目的前端框架、构建工具、组件库、样式方案、路由、状态管理、已有组件、已有渲染机制和已有 Markdown 文件，再选择当前项目对应的渲染适配器。

如果项目已有组件库，应优先复用；但 Skill 只能描述组件语义，不能把某个组件库写成通用依赖。

## 6. Skill 内部目录结构

Skill 必须包含：

```text
<skill-name>/
├── SKILL.md
├── scripts/
│   ├── build_site.py
│   ├── validate_markdown.py
│   └── check_design.py
└── references/
    ├── markdown-spec.md
    ├── design-principles.md
    ├── workflow.md
    ├── component-contract.md
    └── self-checklist.md
```

`scripts/` 存放 Markdown 解析、网页生成、格式校验、页面结构检查、主题检查和响应式检查脚本。`references/` 存放 Markdown 规范、设计原则、页面流程、组件配置规则、数据展示规则和自检清单。

## 7. 多主题和多项目目录

每次执行时，根据用户输入的主题生成独立目录，不得覆盖其他主题：

```text
outputs/<topic-slug>/
├── design/
├── content/
│   ├── pages/
│   ├── site-structure.md
│   └── data-display.md
├── generated/
└── README.md
```

设计文件描述可复用的方法，内容文件描述当前项目的页面。`<topic-slug>` 必须稳定、可读且不可重复覆盖。

## 8. 新建网页与复用网页

### 新建网页

如果当前项目没有可复用的页面架构，AI 必须在建立网页代码的同时建立对应的页面 Markdown、页面结构和必要配置，不能先写一套无法配置的页面代码，再事后补 Markdown。

### 复用已有架构

如果当前项目已经存在可用的页面架构和 Markdown，可以复用当前代码和 Markdown。根据新需求适当调整页面 Markdown；只有现有代码不支持所需能力时，才扩展程序代码，并同步更新 Markdown 规范。

## 9. 执行顺序

1. 识别页面需求并选择风格 Prompt。
2. 读取所选风格 Prompt。
3. 研究用户主题、目标用户、核心信息、数据类型、使用场景和参考资料。
4. 分析当前项目的技术架构、已有组件和渲染能力。
5. 判断是新建网页还是复用已有架构。
6. 提取需要继承的视觉语言、布局原则、交互原则、数据展示原则和响应式规则。
7. 根据新的业务目标设计页面，不复制不必要的旧页面结构。
8. 在新建网页时同步建立代码和 Markdown；在复用架构时优先复用并调整已有 Markdown。
9. 根据当前项目框架实现或扩展程序代码能力。
10. 通过当前项目的渲染适配器生成网页。
11. 执行内容、设计、布局、主题和代码一致性检查。

## 9. 修改决策规则

修改文案、标题、导航、区块顺序、卡片内容、主题参数、布局参数或数据展示方式时，只修改页面 Markdown。

新增组件、Markdown 语法、布局模式、主题能力、图表类型、交互行为或可配置参数时，同时修改代码和 Markdown 规范，并用页面 Markdown 验证新能力。

修改 API、数据抓取、数据处理、状态管理、性能优化或内部错误处理时，可以只修改代码；如果影响 Markdown 的使用方式，必须同步更新规范。

如果 Markdown 无法表达需求，不得直接把需求硬编码到页面中，必须先扩展渲染能力和 Markdown 规范。

## 10. README 要求

每个主题目录必须生成 `README.md`，说明主题、技术架构、Markdown 文件位置、设计规范位置、内容和主题修改方式、运行生成脚本的方法、启动预览的方法、何时需要修改代码以及如何执行自检。

## 11. 核心原则

> 该 Skill 负责把网页设计过程变成可重复执行的工作流。每次创建网页时，先研究主题和当前项目，再继承设计思路，根据业务目标重新组织页面，最后使用当前项目对应的技术架构完成实现。程序代码负责提供网页能力，Markdown 负责配置当前页面，两者共同控制最终渲染结果。
