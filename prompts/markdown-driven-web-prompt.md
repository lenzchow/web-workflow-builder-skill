# 可复用网页设计与 Markdown 驱动开发 Prompt

## 1. 目标

建立一套“设计模板 + 页面 Markdown + 项目代码”的网页生成工作流。

当需要生成网页时，先根据页面需求选择合适的风格 Prompt，再读取其中的 Markdown 设计模板，继承对应的设计、架构和 UI 思路；然后根据本次业务目标生成页面 Markdown，并由当前项目的代码实现和渲染网页。风格 Prompt 可以有多个，当前项目只是其中一种实现。

每次创建新网页时：

1. 读取已有的设计模板；
2. 分析当前项目的技术架构；
3. 根据新的业务目标重新组织页面；
4. 通过程序代码实现网页能力；
5. 通过 Markdown 配置页面内容和可配置表现；
6. 使用代码与 Markdown 共同完成页面渲染。

Markdown 不替代代码，代码也不能完全取代 Markdown。

## 2. 代码与 Markdown 的职责

### 程序代码负责“能做什么”

程序代码负责当前项目的框架适配、页面渲染、组件实现、数据请求和处理、API、业务逻辑、交互行为、状态管理、路由、Markdown 解析、主题和布局实现能力、默认配置及错误处理。

### Markdown 负责“当前页面怎么展示”

Markdown 负责页面文案、标题、导航名称、页面区块、区块顺序、卡片、表格、图表和列表、组件参数、数据展示方式、主题配置、布局参数、显示和隐藏条件，以及加载、空状态和错误提示文案。

核心关系：

```text
程序代码定义可用能力
Markdown 配置当前页面
代码和 Markdown 共同控制最终渲染结果
```

## 3. 框架无关原则

不得预设所有项目都使用 React、Vue、HTML、Ant Design 或其他固定技术。

每次开始前，先检查当前项目的前端框架、构建工具、组件库、样式方案、路由、状态管理、已有组件、已有渲染机制和已有 Markdown 文件，再根据项目实际架构选择渲染方式。

```text
Markdown 内容 → 设计规范 → 页面配置 → 当前项目的渲染适配器 → 目标框架网页
```

框架和组件库属于项目实现细节，不属于通用设计规范。

## 4. 设计模板与页面内容

需要保留的是网站的设计方法，而不是当前网站固定的页面结构。

设计模板应记录视觉设计、页面组织、交互设计、数据展示原则、主题变化、响应式规则和可读性要求；不得写死当前项目的页面数量、导航名称、业务文案、固定区块、具体框架或具体组件库。

新项目应继承设计语言，但可以根据业务目标自由增加、删除和重新组合页面区块。

设计模板回答“应该怎样设计”，页面 Markdown 回答“这次要展示什么”。除非用户明确要求沉淀新的通用规则，否则不要把当前页面细节写回设计模板。

## 5. Markdown 文件分层

建议分为可复用设计模板和当前项目内容文件：

```text
template/
├── design-principles.md
├── visual-language.md
├── layout-patterns.md
├── interaction-patterns.md
├── data-display-principles.md
└── responsive-rules.md

content/<project-name>/
├── pages/
├── site-structure.md
├── data-display.md
└── README.md
```

模板文件描述跨项目复用的设计思路；内容文件描述本次项目需要展示什么。

## 6. AI 修改规则

如果是新网页，必须在编写网页代码的同时建立页面 Markdown 和必要配置；如果是复用已有架构，应优先复用并调整已有 Markdown，只有现有代码不支持需求时才扩展代码。

### 只修改 Markdown

修改页面文字、标题、导航、区块顺序、卡片和表格内容、主题参数、布局参数或数据展示方式时，修改对应 Markdown，不直接修改业务代码。

### 同时修改代码和 Markdown

新增组件、Markdown 语法、布局模式、主题能力、图表类型、交互行为或可配置参数时：

1. 修改程序代码提供新能力；
2. 更新 Markdown 规范或组件说明；
3. 使用 Markdown 配置新能力；
4. 检查页面是否按 Markdown 正确渲染。

### 只修改代码

API、数据抓取、数据处理、状态管理、性能优化和内部错误处理可以只修改代码；如果修改影响 Markdown 的使用方式，仍须同步更新 Markdown 规范。

## 7. 页面创建流程

1. 读取已有设计模板，确认需要继承的设计原则。
2. 分析当前项目的技术栈、渲染方式、组件能力、数据来源和页面结构。
3. 根据新的业务目标重新决定页面区块、信息层级、展示顺序和交互流程，不直接复制旧页面结构。
4. 根据当前项目框架实现或扩展代码能力。
5. 生成当前项目专属的页面 Markdown 和必要配置。
6. 使用当前项目的渲染方式生成网页并执行自检。

## 8. 自检要求

检查 Markdown 是否完整、页面结构是否正确、设计思路是否一致、主题是否可读、页面高度和滚动是否正常、代码是否硬编码覆盖 Markdown、是否存在未注册组件，以及代码和 Markdown 是否保持一致。

## 9. 核心原则

> AI 通过程序代码完成网页开发，通过 Markdown 配置页面内容和可配置表现。代码负责提供能力，Markdown 负责组织当前页面。设计规范保存可复用的设计思路，页面 Markdown 根据业务目标自由变化。
